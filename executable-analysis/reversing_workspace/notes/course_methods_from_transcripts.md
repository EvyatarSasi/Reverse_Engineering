# שיטות פתרון מתוך תמלולי הקורס

מסמך זה מחלץ **רק את שיטות העבודה** שהמרצה הדגים, לא את כל תוכן הסרטונים.
המקור: `materials/video_transcripts/`. התמלולים הם תמלול אוטומטי ומכילים רעש —
חולצו רק הצעדים המתודולוגיים הברורים.

## איך המרצה פותר riddle4
מקור: `פתרון riddle4.txt`

1. טוען את ה-exe ל-IDA. מאתר את `main` לפי תבנית הקומפיילר של Visual Studio
   (כתובת באזור 0x40xxxx) ועושה double-click כדי לקפוץ ל-main.
2. מזהה פונקציה שנקראת כמה פעמים ומקבלת **כתובת** של משתנה לוקלי + מחרוזת פורמט
   `%d`. מסיק שזה `scanf`. שתי אינדיקציות:
   - מחרוזת פורמט `%d` — מעט פונקציות מקבלות `%d` (printf/scanf).
   - הפונקציה מקבלת `lea eax,[var]; push eax` כש-`var` עדיין לא אותחל → זה scanf,
     כי printf היה מקבל ערך שכבר נמצא במשתנה.
   - לאישור סופי: drill-down אל תוך הפונקציה ורואים בפנים קריאה אמיתית ל-scanf.
3. נותן שם לפונקציה עם מקש `N` (rename).
4. קונבנציית קריאה: אחרי ה-call יש `add esp, 8` בצד הקורא → **cdecl**.
   ערך החזרה ב-EAX לא בשימוש (מיד נדרס) → מתייחס לפונקציה כ-`void`.
5. מזהה את `printf` באותה שיטה (פורמט עם `%d`/`"*"`, cdecl).
6. זיהוי ארגומנטים/לוקליים לפי offset יחסית ל-EBP אחרי הפרולוג הסטנדרטי:
   ארגומנט A ב-`EBP+8`, ארגומנט B ב-`EBP+0xC`. משתנים לוקליים ב-`EBP-offset`.
7. **קודם מסתכלים על המבנה** (zoom out ב-graph view) לפני קריאת פקודות בודדות:
   מזהה nested loop (לולאה חיצונית + פנימית) לפי ה-back-edges בגרף.
8. מאתר מוני לולאה: משתנה שמאותחל (ל-1) לפני הלולאה ומקודם בתוכה
   (`mov ecx,[i]; inc ecx; mov [i],ecx`) → זה אינדקס `i`. ההשוואה `i <= B`
   (jg = קפיצה אם גדול → יוצא כשגדול, נשאר כש-`i<=B`).
   הסבר: `inc` דורש רגיסטר כי אי-אפשר לקדם זיכרון ולכתוב בפעולה אחת.
9. לולאה חיצונית: `var8 = A` בהתחלה, מקודם ב-`-1` כל איטרציה → `j`. `while j>0`.
10. printf מדפיס `"*"` בתוך הלולאה הפנימית; printf של ירידת שורה אחרי הפנימית.
11. שחזור ל-C עם הצהרת `__cdecl` מפורשת. אימות: קומפילציה ב-Visual Studio
    והשוואת הפלט (מודפס מלבן/משולש של כוכביות).
12. טיפ כללי: Visual Studio עוטף פונקציות Windows/CRT — חופרים פנימה דרך ה-wrappers
    עד שמוצאים את קריאת ה-API האמיתית.
> המרצה ציין במפורש: riddle4 **"דומה מאוד"** לתרגיל הראשון במטלה — כלומר ל-rect.

## איך המרצה פותר carrot ו-pixies
מקור: `פתרון carrot.txt`, `פתרון pixies.txt`

### carrot
1. טוען ל-IDA. בלוק קוד אחד; ממזער כדי לראות את כל הבלוק.
2. מתעלם מ-boilerplate (security cookie, פרולוג) — "פשוט לא מעניין".
3. בסוף יש call לפונקציה עם פורמט `%s\n` → `printf` (cdecl, `add esp, 8`).
4. הפונקציה בונה מחרוזת ב-buffer לוקלי (`var_1C`, מכונה STR).
5. המחרוזת נבנית מהעתקת ~6 מקטעים של 4 בתים כל אחד
   (`mov eax,[const]; mov [str+off],eax`) מכתובת בזיכרון — הפיצול ל-4 בתים מבלבל בכוונה.
6. double-click על כתובת המקור (למשל 0x403018) → צפייה ב-**Hex view**.
   המרת הבתים ל-ASCII (פעולת "convert to string" של IDA) → קריאת המחרוזת.
7. אחרי טעינת המחרוזת `eax=1`, ואז `shl` שלמעשה לא עושה כלום (artifact של הקומפיילר).
8. שיטה מרכזית: **לעקוב אחרי המקורות** של ההעתקות ולהמיר hex→ASCII כדי לשחזר את
   המחרוזת הקבועה.

### pixies
1. טוען ל-IDA. טוען 4 ערכים (0x0A, 0x27, 0x3B, 0x63) ל-4 משתנים.
2. משווה `[ebp+argc]` (מספר ארגומנטים) ל-2 → בדיקת ארגומנט שורת-פקודה.
   `main` דוחפת למחסנית envp, argc, argv. בלי ארגומנט `argc=1` (שם הקובץ עצמו).
   כדי לעבור צריך `argc=2` → להעביר ארגומנט אחד. (`jnz` בודק `argc==2`.)
3. `printf` עם `%c%c%c%c` → מדפיס 4 תווים (cdecl).
4. כל אחד מ-4 הערכים עובר `XOR 0x42`, התוצאה נשמרת ומודפסת.
5. פתרון ידני: לכל קבוע מחשבים `const ^ 0x42` ומדפיסים כ-char →
   מקבלים את המחרוזת (למשל "Hey!"). שיטה: **XOR כל קבוע עם 0x42 → ASCII**.
6. הרצה: pixies דורש ארגומנט אחד; בלי ארגומנט לא מדפיס כלום (יוצא).

## איך המרצה פותר Wonderland שלב 0 ושלב 1
מקור: `פתרון שלב 0 wonderland.txt`, `פתרון שלב 1 wonderland.txt`

### שלב 0
1. לפני IDA — מריץ את ה-executable, מנסה סיסמאות, צופה בפיצול correct/wrong.
2. הכניסה לפונקציית השלב היא דרך **switch-case / jump table** בכתובת ~0x41xx00,
   המכיל את כל שלבי Wonderland. כאן אנחנו ב-case 0.
3. `fgets` לתוך buffer = user_input (rename ל-`user_input`).
4. רצף `strcpy` ו-`strcat` שבונה מחרוזת `destination` ממקורות.
5. `strncmp(len, destination, user_input)`: `push eax` (eax = תוצאת strlen =
   אורך destination, פרמטר ראשון), ואז כתובת destination וכתובת user_input.
   כדי לעבור: `user_input` חייב להיות שווה ל-`destination`.
6. כדי לחשוף את destination — **עוקבים אחרי המקורות** של strcpy/strcat
   (IDA מציג source→dest). זו הסיסמה.
7. EBP+offset = משתנים לוקליים על המחסנית; IDA מתייג למשל "destination" ב--0x400
   יחסית ל-EBP.
8. הרצה: מזין מספר שלב 0, ואז הסיסמה הנכונה → "Win!" / מעבר לשלב 1.
> שיטה: static — שחזור מחרוזת destination ע"י מעקב אחרי מקורות strcpy/strcat.

### שלב 1
1. מריץ שלב 1: מזין level 1, מתבקש "second password".
2. הגעה דרך jump table ל-case 1.
3. מסנן הדפסות לא חשובות. מחפש את מיקום ה-"correct". כדי להגיע צריך לעבור
   `test eax,eax; jz correct`. ה-eax מגיע מפונקציית השוואה (כמו strncmp בין שתי מחרוזות).
4. דומה מאוד לשלב 0, אך עם **לולאת XOR**. יש מחרוזת קבועה
   `STR = "Into the rabbit hole"` (rename `into_the_rabbit_hole`).
5. גישת **wishful thinking** — מניחים שהמחרוזת היא הבסיס.
6. לולאה על user_input: מאתר מונה (מאותחל ל-0, מקודם `i++`).
   `var_C = strlen(user_input)` → אורך הקלט, גבול הלולאה. `for i in range(len)`.
7. בתוך הלולאה: לוקח `user_input[i]` (כתובת לפי EBP + i, mov בית אחד),
   עושה `XOR` עם ערך hex, וכותב חזרה למחרוזת.
8. אחר כך `strncmp` של התוצאה מול "Into the rabbit hole". כדי לעבור:
   כל תו בתשובה הנכונה XOR עם הקבוע נותן את "Into the rabbit hole".
   כלומר התשובה = כל תו של "Into the rabbit hole" XOR עם אותו ערך hex.
9. פתרון ב-Python: לוקחים "Into the rabbit hole", XOR כל תו עם הקבוע → הסיסמה.
   הדבקה כקלט → "Level 1 Correct. You may enter."
> שיטה: static; שחזור מחרוזת קבועה + מפתח XOR, חישוב ההיפוך ב-Python.

## כלים ושיטות שחוזרים על עצמם
- **IDA**: Graph view, Text view, חלון Strings, Xrefs, מתן שמות (`N`), הערות.
- **איתור main**: תבנית קומפיילר; ב-Wonderland — jump table / switch-case לכל שלב.
- **זיהוי פונקציות ספרייה** לפי מחרוזות פורמט (`%d`,`%s`,`%c`) וע"י drill-down דרך
  wrappers עד ל-API האמיתי.
- **scanf מול printf**: scanf מקבל כתובת של לוקלי לא-מאותחל; printf מקבל ערך/מחרוזת.
- **קונבנציית קריאה**: cdecl מזוהה ב-`add esp, N` בצד הקורא אחרי call;
  בודקים אם ערך החזרה (EAX) בשימוש. (חשוב במיוחד ל-rect לפי ה-brief.)
- **מסגרת מחסנית**: ארגומנטים ב-`EBP+8`, `EBP+0xC`...; לוקליים ב-`EBP-offset`.
- **קריאת מבנה תחילה** (zoom out), זיהוי לולאות לפי back-edges, איתור מוני לולאה
  (אתחול + inc/dec).
- **שחזור מחרוזות קבועות**: Hex view, המרה ל-ASCII / "convert to string".
- **פתרון בדיקות XOR** ע"י חישוב ההיפוך ידנית או ב-Python.
- **אימות** ע"י הרצה / קומפילציה (ל-rect: קומפילציית C ב-Visual Studio והשוואת פלט).

## מה אסור לעשות במטלה
- שלבים 2-3: **static only**.
- שלבים 4-5: static + dynamic observation מותר, אבל **אסור patching**: לא לשנות קוד,
  רגיסטרים, זיכרון, או בתים ב-executable; לא לעקוף בדיקות ע"י מניפולציה של מצב ריצה.
- אסור: angr, symbolic execution, Frida, bruteforce automation, unpackers,
  decompiler בלבד כראיה יחידה, ניתוח בינארי אוטומטי מתקדם.
- אסור לנחש תשובות; כל מסקנה חייבת לצטט ראיה מהקבצים בתיקייה.
